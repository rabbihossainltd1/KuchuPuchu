# Owner round 35 — the composer caret, the link colour, the QR screen — 2026-10-18

The owner sent two screenshots from the Android app and named four things.

---

## 1. The message bar's caret did not sit at the end of the text

**What the owner wrote:** *"massage bar a massage type korle massage er seshe je dag ta thake ota massage er last a thakche na prothome thakleo boro massage type korle aste aste word er upore overlap korche thik thakche na."*

**What it was.** The composer painted the typed text TWICE:

1. a visible `Text()` that drew the glyphs, and
2. a `BasicTextField` with `color = Color.Transparent` on top of it — an
   invisible field whose only visible job was to draw the **caret** and take
   the keyboard.

The two layers measured **differently**, so the caret drifted. The reason is
a Compose detail:

* `Text()` merges `LocalTextStyle.current` — and the app's `MaterialTheme`
  provides Material 3's `bodyLarge`, whose **letterSpacing is 0.5sp**.
* `BasicTextField(textStyle = …)` uses the style it is given **as-is** — it
  never takes `LocalTextStyle`, so its letter-spacing is **0sp**.

Every character in the visible line was therefore ~0.5sp wider than the same
character in the invisible field, and the caret — drawn by the field — sat
that much further to the LEFT. The gap grows with the message, which is
exactly what the owner saw: the caret started near the end and walked onto
the words as the line got longer. The screenshot shows it plainly — a
26-character message with the caret sitting between `…hehg` and `ge`.

**The fix** (`ChatScreen.kt`): both layers now take **one** style object.

```kotlin
val composerTextStyle =
    TextStyle(
        fontSize = 14.sp,
        lineHeight = 20.sp,
        letterSpacing = 0.sp,      // no inherited letter-spacing
        fontFamily = FontFamily.Default,
    )
```

* the visible `Text()` uses `style = composerTextStyle` (so it no longer
  inherits `LocalTextStyle` at all), and
* the field uses `textStyle = composerTextStyle.copy(color = Color.Transparent)`.

Same font, same size, same line height, same letter-spacing, same width —
the two layers can no longer measure differently, so the caret is always
exactly after the last character.

## 2. A link inside a message was invisible

**What the owner wrote:** *"link massage dekho valo bojha nai na text blue a ar bubble o blue tai link bojha jai na valo."*

**What it was.** `MessageMarkup.annotate()` was called with
`linkInk = chatAccent(theme)` — the chat theme's accent. On the default
**blue** chat, that accent is `0xFF2F6FED`, which is *exactly* the colour of
my own bubble (the blue gradient `0xFF2F6FED → 0xFF1E40AF`). A blue link on
a blue bubble, underlined — the underline was the only clue, and with a long
URL the underlined lines read as overlapping garbage.

**The fix** (`ChatScreen.kt`): the link colour is now picked against **the
bubble it sits on**, not against the theme.

```kotlin
internal fun linkInkFor(theme: String, mine: Boolean): Color {
    val bubble = /* the bubble's own colour for this theme and side */
    return if (bubble.luminance() < 0.45f) Color(0xFFFFFFFF) else Color(0xFF17409B)
}
```

* a **dark** bubble (my blue bubble, the dark-navy other bubble, the night
  chat) takes **white**;
* a **light** bubble (gold, cream, mint, rose) takes a **deep blue** that
  reads on all of them.

Mentions take the same colour, so an @mention is as readable as a link.

## 3. The scan pane's box border

**What the owner wrote:** *"box border ta remove koro scan screen a"*.

The scan pane carried a `2.dp` accent border around the whole empty-state
card (added in round 33 to make it look like a viewfinder). It is gone; the
scanner's own corner brackets are the frame now.

The **QR code** panel keeps its frame on purpose — the white quiet zone
around the code is what lets a scanner read it.

---

## 4. The My code / Scan switch: no animation, and the wrong icons

**What the owner wrote:** *"upore switching animation nai my qr to scan a geleo"* and
*"ar 2 ra icons e change hobe … text thakbe na just icon nav bar er moto same rounded shob switching animation o thakbe"*.

**What it was.** The two panes swapped in a single frame — one was removed
and the other appeared, so the switch looked like a jump cut. The tabs wore
the stock Material `QrCode` / `QrCodeScanner` glyphs with a text label.

**The fix** (`QrScreen.kt`, `QrIcons.kt`):

* the owner's **own** glyphs, redrawn as `ImageVector`s (no PNG ships): a
  code block with a person for **My code**, a viewfinder frame for **Scan**;
* the tabs are **icon only** — no label — in the app's own nav-bar language:
  a rounded container, the active tab filled with the accent and its glyph
  in white, the other in muted ink, and the icon itself scaling between
  `0.92f` and `1f`;
* the label survives as the **accessibility name**, so a screen reader still
  says what the tab does;
* the panes now swap through `AnimatedContent` — they slide across each
  other and fade, and the size change is animated too.

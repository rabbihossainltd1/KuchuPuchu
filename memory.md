- DIAGNOSIS (production evidence, read-only): live app.js was byte-identical to the repo; D1 (kuchupuchu-v3-apac) showed the web session belongs to user `f9864c26` (web-wacf1461906384) with 6 visible memberships, hidden_json `{}`, no request_from; error_log had no route crashes. Reproduced by inserting a temporary diag sessions row (deleted afterwards): live `GET /api/me` 200 and live `GET /api/conversations` **200 with {"items":[6 chats]}** — the server was perfect.
- ROOT CAUSE: `public/app.js` `loadConvs()` read `r.conversations` while the server returns `{ items }` (marker-poll shape). The silent catch rendered the empty state — no error anywhere. Messages route already used `r.items`; only the list load was stale.
- AGGRAVATOR: `public/sw.js` caches `/app.js` cache-first under `kp-shell-v1`; without renaming the cache key no deployed fix would ever reach existing installs.
- FIX: `loadConvs()` reads `(r.items || [])`; SW cache bumped `kp-shell-v1` → `kp-shell-v2` (with a comment explaining the bump rule). Regression pins in case 55 (client reads r.items, never r.conversations, shell key past v1) alongside case 04's existing server-side items pin.
- DEPLOY FACT LEARNED: Cloudflare **Workers Builds auto-deploys the Worker on every push to main** (schema_meta fingerprint + web_push_subs table prove today's merge went live without any manual wrangler deploy). Merging the hotfix PR = it ships.

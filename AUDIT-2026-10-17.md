### H2 — The whole classroom feature is silently dead in production without an undocumented secret
`classroomBridgeKey()` (`src/worker/index.ts:2839`) returns `null` whenever
`env.LARAVEL_BRIDGE_KEY` is unset, which makes every `/api/classroom/*` and `/ws/classroom/*`
route fail closed with `503 CLASSROOM_UNAVAILABLE` (fine, fail-safe) — but **no doc anywhere
tells the owner to set it**. `README.md`, `FIREBASE-SETUP.md`, and `docs/cloudflare-token.md`
document `GOOGLE_WEB_CLIENT_ID`, `FCM_CONFIG`, `FCM_CREDENTIALS`, `TURN_KEY_ID`,
`TURN_API_TOKEN`, `DEBUG_KEY` as things to `wrangler secret put`, but never mention
`LARAVEL_BRIDGE_KEY` or `LARAVEL_CLASSROOM_ORIGIN` (the latter IS in `wrangler.toml [vars]`,
so that half is fine). Net effect: ship this, and the "Class" tab will sit there answering 503
to every user until someone notices and manually runs
`npx wrangler secret put LARAVEL_BRIDGE_KEY` — which isn't written down anywhere in the repo.

## 🟡 MEDIUM

### M1 — Documentation has drifted hard from what's actually deployed and actually built
- `README.md` "What talks to what" diagram, "Repo map", and `## Web client` section all still
  describe `public/` (dependency-free HTML/JS) as *the* served browser client. It isn't:
  `wrangler.toml [assets] directory = "./web/dist"` + `public/RETIRED.md` ("Nothing in this
  directory is deployed any more") both say the React app under `web/` is production since the
  "slice J cutover". README was never updated for that cutover, nor for the ~30 web "slice"
  features added afterward (profile drawer, contacts, scheduled/disappearing, hidden chats,
  archive/pin, calls, push, and now the classroom tab), nor for the classroom/VX work at all.
- `PROJECT_UNDERSTANDING.md` is explicitly self-dated 2026-10-01 and still calls the web client
  "no build step … `public/`" — same drift, plus it predates this feature entirely.
- `ARCHITECTURE-v3.md` is the original pre-build plan; fine as history, but nothing marks it
  superseded.
- Zero mentions of "classroom" or "VX" anywhere in `docs/`, `ARCHITECTURE-v3.md`,
  `PROJECT_UNDERSTANDING.md`, or `PHONE_AUTH_PLAN.md`. The only trace of this feature besides
  the code itself is `memory.md` (dev log, last entry 2026-10-13 — predates this commit) and
  the test files. A large cross-realm identity-bridge feature (new DB tables, a new Durable
  Object, 8 new API routes, a new WebSocket namespace, Android + Web UI) shipped with no
  architecture doc. Given this repo's own convention (every other feature slice got a `docs/*`
  page), this one breaking the pattern is worth fixing before more work builds on it blind.

### M2 — Per-user media storage has no quota; abandoned single-POST uploads are still never swept
Carried over from `AUDIT-2026-09-21.md` M3, re-checked and still true: `collectOrphanedMedia`
(`index.ts:15284`) is only invoked from known delete paths (message delete, status expiry, call
hangup, etc.) — there's no cron or query that finds `files` rows with `conv_id IS NULL` that
were never attached to anything and reclaims them. No per-user total-bytes cap exists either
(only per-file ceilings: 100MB image / 2GB video / 5GB doc / 100MB voice). Low urgency at
current scale, real cost at any scale.

### M3 — `native-android/app/debug.keystore` is still committed
Unchanged from `AUDIT-2026-09-21.md` M4. Anyone with read access to this repo can sign an APK
that Android will accept as an in-place update for `app.kuchupuchu.android`. README already
flags this as a known sharp edge and says future releases need a real signing-key migration
with explicit owner approval — that migration still hasn't happened.

### M4 — A few raw `Log.d` calls crept back into the Android client
`ChatScreen.kt:5347,5454,5463,8649` and `SendFlight.kt:156` call `android.util.Log.d(...)`
(tags `kpclip`, `kpfx`) with debug-ish payloads (clip MIME types, internal state keys). The
*previous* audit's "Verified GOOD" list explicitly said "zero `Log.*` in app" — that's no
longer true. Nothing secret is logged and `proguard-rules.pro` has no log-stripping rule, so
these ship into release logcat too. Not a security bug, just hygiene regression + no contract
test guards against it (case 18 doesn't check for this).

### M5 — Secret-scan coverage is narrow (3 patterns only)
`scripts/secret-scan.ts` only matches GitHub PATs, AWS access keys, and PEM private-key blocks.
It would miss a leaked Google API key (`AIza…`), a Firebase web config object, a Stripe/OpenAI
key, or any other provider's token shape. Manually grepped the whole tree for several common
secret shapes (`AIza...`, `sk-live/sk-test...`, generic `secret/password/api_key = "..."`
assignments) and found nothing — repo is clean right now — but the automated gate itself is
thin and would not have caught it if it weren't.

## 🟢 LOW / INFO

- **L1 — `src/worker/index.ts` is a 15,800-line single file.** Everything (routing, auth,
  messaging, calls, statuses, push, AI, classroom bridge, admin/debug) lives in one module.
  It's internally well-organized (clear section comments, consistent helper naming) and typechecks/tests
  clean, but at this size it's a standing tax on review time and merge conflicts — a candidate
  for splitting by route domain once a quiet window exists. Same shape concern applies to
  `ChatScreen.kt` (~12.5k lines) on Android.
- **L2 — CORS `*` with `Authorization` allowed** (`index.ts:139` etc.) — unchanged from the
  prior audit's L1, still an accepted trade-off for a token-bearer, cookie-less API.
- **L3 — Public TURN fallback** (`openrelay.metered.ca`) still in use per README's own
  "Known sharp edges" — unchanged from prior L4.
- **L4 — `shots/` (3.7 MB of PNG screenshots) is tracked in git.** Harmless, but it's
  binary-diff weight in every clone/fetch; consider Git LFS or dropping stale ones if the
  folder keeps growing.
- **L5 — No ESLint, only Prettier + `tsc --noEmit`.** Typecheck catches real bugs but not
  things like unused vars across files, `no-floating-promises`, or dead branches; worth
  weighing against the size in L1.
- **L6 — `docs/cloudflare-token.md`'s secret list should gain `LARAVEL_BRIDGE_KEY`** once H2
  above is written up, so the "what needs Workers Scripts Edit" table stays authoritative.

## ✅ Re-verified GOOD (fixed since the 2026-09-21 audit)
- **H2 (old) "logged-out SIM takeover"** — fixed. Google-bound accounts with no live device
  now get `GOOGLE_REQUIRED` and must prove the linked Google subject before a session is
  minted (`index.ts:7405-7412`, shipped 2026-10-12 as "H2 option 2"); unbound accounts keep the
  old reinstall UX unchanged. Covered by `test/cases/86-h2-google-proof.mjs`.
- **H3 (old) "view-once fetchable without spending"** — fixed. The first non-sender `GET
  .../media` on a view-once message now spends it atomically at fetch time, not at the
  client-optional `/view` call. Covered by `test/cases/38-viewonce-spend-on-fetch.mjs`.
- **M2 (old) "all rate limits per-isolate"** — substantially fixed. A new D1-backed
  `rateLimitGlobal()` (`index.ts:2464`) now backstops every auth-sensitive route (verify-phone,
  google-bind, login, recovery lookup/start/confirm, directory search, link/identity exchange,
  and all the new classroom routes) on top of the existing fast in-memory bucket, closing the
  "cap × isolate-count" gap the prior audit flagged.
- Production dependency tree is clean: `npm audit --omit=dev` → **0 vulnerabilities** (the only
  runtime deps are `react`/`react-dom`). The 6 findings `npm audit` reports unfiltered are all
  transitive to `wrangler`/`miniflare` (dev-only, local preview tooling, never shipped).
  `security:secrets` passes; manual grep for common leaked-key shapes found nothing.
- All 91 worker test files / 3887 assertions pass locally, including the two new classroom
  suites (`97-classroom-entitlement-bridge.mjs`, `98-classroom-mesh.mjs`) and
  `95-identity-propagation.mjs`, which exercise the HMAC assertion signing/verification,
  upstream-failure fail-closed behavior, room-token gating before the WebSocket DO accepts a
  connection, and the `MAX_PARTICIPANTS = 6` mesh cap.
- `ClassroomSignal` Durable Object is signalling-only by design (comment says so, code matches):
  it validates `userId` shape, caps room size, validates frame types/sizes before relaying, and
  never sees audio/video bytes — that's the right shape for a P2P mesh relay.
- Worker and Web both typecheck clean; `npm run build:web` / `build:web:prod`,
  `verify:web-sw`, and `check:web-stickers` all pass; Prettier formatting is clean repo-wide.
- Android-side source validation (`validate:android` — manifest, resources, dependency
  pinning, lint gate) passes; `debug.keystore` aside, exported component count stays minimal.
